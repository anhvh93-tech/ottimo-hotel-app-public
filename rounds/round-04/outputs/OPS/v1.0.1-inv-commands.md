## Luật chung – đọc một lần

1. Mỗi bước là **một khối lệnh**. Bấm vào khối, chọn hết, sao chép (⌘C), dán vào Terminal (⌘V), rồi nhấn **Enter**. Chép **cả khối**, kể cả khi khối dài. Không sửa gì bên trong, trừ chỗ tài liệu bảo thay.
2. So kết quả với mục **"Đúng là"** của bước đó. Đúng thì làm bước tiếp theo. **Khác** thì dừng lại, chụp màn hình Terminal và gửi đội. (Ở bước dán webhook, đừng chụp màn hình: xem bước B8.)
3. Máy hỏi `password` hoặc `[sudo] password for ottimo-admin` thì gõ **mật khẩu của tài khoản `ottimo-admin`** (không hiện chữ khi gõ), rồi nhấn Enter. Đừng gửi mật khẩu này cho ai.
4. Lần đầu nối tới `desk.ottimo.vn`, máy có thể hỏi `Are you sure you want to continue connecting (yes/no/[fingerprint])?`. Chỉ gõ `yes` khi **ngay phía trên** có câu `This host key is known by the following other names/addresses:` (nghĩa là đây đúng là máy chủ anh/chị đã từng nối bằng địa chỉ IP). **Không** thấy câu đó thì gõ `no`, dừng lại, báo đội. Thấy chữ **`WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED`** thì cũng **dừng**, báo đội, không làm tiếp.
5. Không lệnh nào trong tài liệu này in ra mật khẩu, khóa hay URL webhook. Thấy chuỗi dài lạ thì cũng đừng gửi lên chat; chỉ gửi ảnh chụp cho đội qua kênh riêng.
6. Gõ nhầm, hoặc Terminal "treo": nhấn **Ctrl + C** rồi chạy lại đúng bước đó. Mọi bước đều chạy lại được (riêng B5: xem ghi chú ở bước đó).
7. **URL webhook chỉ được dán ở đúng một chỗ**: khi dòng cuối của Terminal là chữ `Webhook URL:` (bước A9/B8). Ở mọi chỗ khác – dấu nhắc của Mac (dòng kết thúc bằng `%`), ô `[sudo] password`, sau chữ `usage:` hay `Connection … closed` – **không dán**. Lỡ dán thì làm mục "Lỡ dán URL ra ngoài dấu nhắc" ở cuối tài liệu.

## Phần A – Staging (bản thử)

Mục đích: đưa bộ cấu hình máy chủ mới lên, rồi tạo tệp bí mật webhook để trống. Có tệp này thì lượt "deploy staging" của bản Google Chat không bị máy chủ từ chối. Tệp trống nghĩa là Chat ở staging đang **tắt**. Đây là trạng thái đúng ở đợt này.

### A1. Lấy bản mới nhất của dự án về Mac

```bash
cd ~/Desktop/hotel-app && git fetch origin && git log -1 --format='%h %s' origin/main
```
**Đúng là:** in ra một dòng gồm một mã ngắn (khoảng 8 ký tự) và một câu. Mã này phải **trùng mã đội nhắn** khi báo "PR #16 đã gộp".

### A2. Đóng gói cấu hình máy chủ

```bash
cd ~/Desktop/hotel-app && rm -f /tmp/ottimo-infra.tgz && git archive --format=tar.gz -o /tmp/ottimo-infra.tgz origin/main product/infra && ls -lh /tmp/ottimo-infra.tgz && shasum -a 256 /tmp/ottimo-infra.tgz
```
**Đúng là:** một dòng kết thúc bằng `/tmp/ottimo-infra.tgz`, dung lượng khoảng 100–300K, rồi một dòng **mã băm** (64 ký tự chữ và số, rồi `/tmp/ottimo-infra.tgz`). Ghi lại **6 ký tự đầu** của mã băm: bước A4 phải ra đúng 6 ký tự đó.

### A3. Gửi gói lên máy chủ

```bash
scp -i ~/.ssh/ottimo_ops /tmp/ottimo-infra.tgz ottimo-admin@desk.ottimo.vn:ottimo-infra.tgz
```
**Đúng là:** một dòng `ottimo-infra.tgz   100% …`.

### A4. Mở gói trên máy chủ

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sha256sum ~/ottimo-infra.tgz && rm -rf ~/ottimo-bundle && mkdir -m 700 ~/ottimo-bundle && tar -xzf ~/ottimo-infra.tgz -C ~/ottimo-bundle && grep -c set-booking-chat ~/ottimo-bundle/product/infra/server/bin/init-secrets.sh'
```
**Đúng là:**
- dòng đầu là mã băm, **6 ký tự đầu trùng** 6 ký tự đã ghi ở A2 (khác thì dừng: gói trên máy chủ không phải gói vừa đóng – chạy lại A2, A3);
- dòng sau là **một con số từ 3 trở lên**, rồi `Connection to desk.ottimo.vn closed.` Nếu ra `0` thì gói chưa có bản Google Chat: báo đội.

### A5. Thay cấu hình staging (có giữ bản cũ để quay lui)

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && set -e && B=/root/ottimo-staging-bundles/infra-$(date +%Y%m%d-%H%M%S) && sudo mkdir -p /root/ottimo-staging-bundles && sudo cp -a /opt/ottimo/infra "$B" && sudo rsync -a --checksum --delete --delete-excluded --chown=root:root --exclude .DS_Store --exclude .out --exclude .work --exclude .env --exclude ".env.*" --exclude server/test/ ~/ottimo-bundle/product/infra/ /opt/ottimo/infra/ && sudo chmod -R go-w /opt/ottimo/infra && sudo chmod 0755 /opt/ottimo/infra/server/bin/* /opt/ottimo/infra/postgres/init/02-roles.sh && echo "BAN CU GIU O: $B" && echo "CAC BAN CU DANG CO:" && sudo sh -c "ls -1d /root/ottimo-staging-bundles/infra-*" && sudo diff -rq --exclude=test ~/ottimo-bundle/product/infra /opt/ottimo/infra && echo "STAGING: CAU HINH MOI DA VAO"'
```
**Đúng là:**
```
BAN CU GIU O: /root/ottimo-staging-bundles/infra-2026…
CAC BAN CU DANG CO:
/root/ottimo-staging-bundles/infra-2026…      (một hay nhiều dòng)
STAGING: CAU HINH MOI DA VAO
```
Bước này **không** dừng hay khởi động lại gì: app staging vẫn chạy như cũ.
Chạy lại bước này lần thứ hai thì lần sau sao lưu **bản mới** (không phải bản trước khi thay). Bản dùng để quay lui là **dòng `BAN CU GIU O` của lần chạy đầu tiên** – tức dòng **cũ nhất của hôm nay** trong danh sách `CAC BAN CU DANG CO`. Gửi đội cả khối.

### A6. Tạo tệp bí mật còn thiếu (webhook để trống)

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo /opt/ottimo/infra/server/bin/init-secrets.sh'
```
**Đúng là:** dòng đầu tiên là
```
init-secrets: created booking_request_chat_webhook in /opt/ottimo/secrets
```
Sau dòng đó là một khối chữ tiếng Anh bắt đầu bằng `Next:`. Khối này chỉ là ghi chú cho đội, anh/chị **bỏ qua**. Lệnh không in mật khẩu hay khóa nào.
- Nếu dòng đầu là `init-secrets: nothing to do – all files exist` thì tệp đã có từ trước, vẫn đúng.
- Nếu dòng đầu ghi thêm tên khác ngoài `booking_request_chat_webhook` thì vẫn được với staging, nhưng chụp màn hình gửi đội.

### A7. Kiểm tệp vừa tạo và cấu hình

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo stat -c "%n uid=%u mode=%a size=%s" /opt/ottimo/secrets/booking_request_chat_webhook && sudo -u ottimo /opt/ottimo/infra/server/bin/dc --profile deploy config -q && echo "CAU HINH: OK"'
```
**Đúng là:**
```
/opt/ottimo/secrets/booking_request_chat_webhook uid=1000 mode=400 size=0
CAU HINH: OK
```

### A8. Kiểm bản sửa "chạy từ thư mục bất kỳ" (ARC yêu cầu)

Lệnh này **cố ý không có `cd /`**.
```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'sudo -u ottimo /opt/ottimo/infra/server/bin/ops-check.sh containers http5xx'
```
**Đúng là:** 2 dòng bắt đầu bằng `ok`:
```
ok   containers: postgres api worker web running, api healthy
ok   http5xx: 0 server errors (5xx) in 35 min
```
(con số có thể khác 0, miễn là dòng bắt đầu bằng `ok`).

### A9. (Chỉ khi anh/chị đã tạo **phòng Chat thử** theo ESC-046) Dán webhook phòng thử

Chưa có phòng thử thì **bỏ qua bước này**: Chat ở staging cứ để tắt.
**Tuyệt đối không** dán webhook của phòng thật "OTTIMO – Yêu cầu đặt phòng" vào staging.
Cách làm **giống hệt bước B8** bên dưới (đọc kỹ phần "Chỉ dán khi…" của B8). Chỉ khác ở đường dẫn: `/opt/ottimo/`, không có `-prod`.
Kiểm trước (phải ra một con số từ 3 trở lên; ra `0` thì **không** chạy lệnh dán, báo đội):
```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo grep -c set-booking-chat /opt/ottimo/infra/server/bin/init-secrets.sh'
```
Rồi lệnh dán:
```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo /opt/ottimo/infra/server/bin/init-secrets.sh --set-booking-chat'
```

### A10. Duyệt deploy staging trên GitHub

1. GitHub → repo → **Actions** → mở lượt chạy mới nhất của `main` (lượt có PR #16).
2. Bấm **Review deployments**, tích **staging**, bấm **Approve and deploy**.
3. Đợi tới khi job `deploy staging` có dấu tích xanh, thường 5–10 phút.

### A11. Kiểm Chat ở staging sau deploy

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo -u ottimo /opt/ottimo/infra/server/bin/dc logs --no-color --no-log-prefix worker | grep "\"msg\":\"chat" | tail -3'
```
**Đúng là** (nếu không làm A9):
```
{"level":"info","msg":"chat: off","reason":"NOT_CONFIGURED"}
{"level":"A","msg":"chat detail level"}
```
Nếu đã làm A9 thì dòng đầu là `{"level":"info","msg":"chat: on"}`.
Dòng thứ hai **đổi dạng** sau khi PR #24 lên staging (đội sẽ nhắn "PR #24 đã gộp"). Từ lúc đó, dòng đúng là:
```
{"level":"info","msg":"chat detail level","detailLevel":"A"}
```
Cả hai dạng đều đúng, miễn là có chữ `A` ở cuối. Bản cũ ghi mức tin vào ô `level` (ô dành cho mức log). PR #24 chuyển nó sang ô riêng `detailLevel`.
Nếu **không in gì** thì gửi ảnh chụp cho đội. Nguyên nhân thường gặp: lỡ bấm duyệt ở A10 **trước** khi làm xong A5–A7. Cách sửa: chạy lệnh dưới đây, rồi chạy lại A11.
```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo -u ottimo /opt/ottimo/infra/server/bin/dc up -d --no-deps worker'
```

Xong phần A: nhắn đội **"Đã xong phần A staging"**, kèm ảnh chụp kết quả A7 và A11.

### B8. Dán URL webhook của phòng "OTTIMO – Yêu cầu đặt phòng"

**Lấy URL** (trên Google Chat, máy tính):
1. Mở phòng **OTTIMO – Yêu cầu đặt phòng**.
2. Bấm tên phòng ở trên cùng → **Apps & integrations** (Ứng dụng và tích hợp) → **Webhooks** → **Add webhook**.
3. Tên: `Desk OTTIMO`. Ảnh đại diện: để trống. Bấm **Save**.
4. Bấm biểu tượng sao chép cạnh webhook vừa tạo. URL bắt đầu bằng `https://chat.googleapis.com/v1/spaces/`.

**Không** dán URL này vào Zalo, email, ghi chú hay tin nhắn cho đội. Chỉ dán vào Terminal ở bước dưới.

**Kiểm trước** rằng máy chủ đã có bản lệnh mới (chặn trường hợp chạy B8 khi chưa làm B5):
```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo grep -c set-booking-chat /opt/ottimo-prod/infra/server/bin/init-secrets.sh'
```
**Đúng là:** một con số từ 3 trở lên. Ra `0` hoặc báo lỗi thì **không** làm tiếp B8: làm lại B3–B5 trước.

**Dán lên máy chủ:**
```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo /opt/ottimo-prod/infra/server/bin/init-secrets.sh --set-booking-chat'

## Quay lui app về v1.0.0 (CHỈ khi đội bảo)

Dùng khi Release v1.0.1 **đã chạy xong** (sau B10), nhưng Desk, api hoặc worker lỗi, **và** tắt Chat (mục "Khi cần tắt Chat ngay") không giải quyết được. Chỉ làm khi đội nhắn **"quay lui app về v1.0.0"**. Lỗi chỉ ở tin Chat thì tắt Chat là đủ, không quay lui.

Không làm mục "Khi cần tắt Chat ngay". v1.0.0 không có tính năng gửi tin Chat nên phòng Chat sẽ không nhận tin mới. Khi đội đưa bản mới lên lại, Chat tự bật, không cần dán lại URL. Đợt này tin ở mức A, không có dữ liệu khách, nên không cần làm gì thêm với các tin cũ. (Nếu sau này đã lên mức B/C mà phải quay lui về bản không có Chat: trong thời gian chạy bản cũ, xóa yêu cầu trên Desk sẽ **không** tạo lời nhắc xóa tin Chat. ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo -u ottimo /opt/ottimo-prod/infra/server/bin/dc ps --format "table {{.Service}}\t{{.Status}}" && sudo -u ottimo /opt/ottimo-prod/infra/server/bin/ops-check.sh containers http5xx'
```
Kết quả gì cũng được (đang có lỗi nên có thể có dòng `FAIL`). Chụp màn hình, gửi đội cùng ảnh R2.

### R3. Sao lưu ngay trước khi quay lui

Chạy lại đúng lệnh **B2**. **Đúng là:** dòng cuối `[backup 2026-…Z] OK: <số> encrypted files in /var/backups/ottimo-prod`.
Lệnh quay lui không đổi dữ liệu. Sao lưu ở đây chỉ để chắc chắn có bản mới nhất nếu có sự cố khác.

### R4. Quay lui app về v1.0.0

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && { sudo -u ottimo /opt/ottimo-prod/infra/server/bin/rollback.sh sha-8b3aec89486f 2>&1; echo "MA THOAT: $?"; } | grep -E "^\[deploy |^another deploy|^usage:|^unknown option|^no previous tag|^digest must|^(Error|ERROR)|^MA THOAT: "'
```
Lệnh chạy khoảng 2–5 phút. Trong lúc đó Terminal có thể đứng yên, cứ đợi. Lệnh **luôn** kết thúc bằng một dòng `MA THOAT: <số>`. Chưa thấy dòng này thì lệnh vẫn đang chạy. **Đúng là:** 6 dòng như sau (giờ và con số có thể khác), rồi `MA THOAT: 0`:
```
[deploy 2026-…Z] deploy sha-8b3aec89486f (previous: sha-…, pull=1, rollback=1)
[deploy 2026-…Z] image digests match the release
[deploy 2026-…Z] api/worker configuration accepted by image sha-8b3aec89486f
[deploy 2026-…Z] 02-roles.sh applied (ottimo_app limits verified by the script)
[deploy 2026-…Z] migrations: <N> applied / <N> in the image journal
[deploy 2026-…Z] OK: sha-8b3aec89486f is live
MA THOAT: 0
```
- Ở dòng `migrations`, hai con số `<N>` **bằng nhau**, vì v1.0.1 không thêm migration. Nếu số đầu lớn hơn thì lệnh vẫn chạy đúng, nhưng chụp màn hình gửi đội.
- Hai dòng cuối phải là `OK: sha-8b3aec89486f is live` rồi `MA THOAT: 0`.

**Khi không đúng như trên:**
- `FAIL: production guard: …` rồi `MA THOAT: 1`: tên bản gõ sai (ví dụ `v1.0.0`), chưa có gì bị đổi. Chép lại đúng khối lệnh R4, chạy lại.
- `another deploy is running` rồi `MA THOAT: 3`: đang có lượt deploy khác, ví dụ một job GitHub chưa xong. Chưa có gì bị đổi. Đợi 5 phút rồi chạy lại R4.
- **Mọi trường hợp khác**: `MA THOAT` khác 0, **hoặc** dòng ngay trên `MA THOAT` **không** phải `OK: sha-8b3aec89486f is live`, **hoặc** có dòng lạ (ví dụ `FAIL: …`, `Error …`). Kể cả khi **không có** dòng `FAIL` nào. Khi đó **không chạy lại**. Chụp màn hình gửi đội ngay, rồi chạy R6 và gửi kèm ảnh. Lệnh quay lui **không** tự trả về v1.0.1 khi hỏng, nên đội sẽ quyết bước tiếp theo.

### R5. Kiểm tên bản sau quay lui

Chạy lại đúng lệnh **R2**. **Đúng là:**
```
DANG CHAY: sha-8b3aec89486f
BAN TRUOC: sha-…        (bản v1.0.1 – đội dùng tên này khi cần đưa v1.0.1 lên lại)
DIGEST v1.0.0: CO
```
Từ lúc này, "bản trước" của máy chủ là **bản lỗi** v1.0.1. Vì vậy **không bao giờ** chạy `rollback.sh` mà không ghi tên bản: lệnh đó sẽ đưa bản lỗi lên lại mà không qua duyệt Release.

### R6. Kiểm toàn bộ máy chủ

Chạy lại đúng lệnh **B12** (`ops-check`). **Đúng là:** mọi dòng bắt đầu bằng `ok`, gồm `containers` (có `landing`), `j16`, `backup`, `disk`, `mem`, `tls`, `http5xx`, và dòng `email_dead` nếu B12 đã có dòng này. Bộ kiểm thuộc cấu hình máy chủ (vẫn là bản v1.0.1), nên kết quả giống B12.

### R7. Kiểm worker v1.0.0

```bash
ssh -t -i ~/.ssh/ottimo_ops ottimo-admin@desk.ottimo.vn 'cd / && sudo -u ottimo /opt/ottimo-prod/infra/server/bin/dc logs --no-color --no-log-prefix worker | grep -E "\"msg\":\"(worker started|chat|job failed)" | head -5; echo HET LOG'
```
**Đúng là:** đúng **một** dòng bắt đầu bằng `{"level":"info","msg":"worker started"`, rồi `HET LOG`.
- Có dòng chứa `chat` (ví dụ `chat: on`): worker vẫn đang chạy bản mới. **Dừng**, gửi ảnh chụp cho đội. Ảnh này không chứa URL.
- Có dòng `job failed`: gửi ảnh chụp cho đội.
- Không có dòng `worker started`, chỉ có `HET LOG`: gửi ảnh chụp cho đội.

### R8. Kiểm bằng mắt rồi báo đội

1. Mở Desk, đăng nhập, mở sơ đồ phòng và danh sách yêu cầu đặt phòng. Mọi thứ hiện như trước.
2. Phòng Chat "OTTIMO – Yêu cầu đặt phòng" sẽ **không** nhận tin mới nữa. Đây là điều bình thường với v1.0.0. Lễ tân xem yêu cầu mới trên Desk (H03) như trước ngày 01/11. Kiểm "Mỗi sáng" ở trên **tạm ngưng** cho tới khi đội đưa bản mới lên.
3. Các bản sửa khác của v1.0.1 cũng tạm mất. Đội sẽ nhắn những việc lễ tân cần làm tay trong thời gian này.
4. **Không** bấm chạy lại Release v1.0.1 trên GitHub, vì làm vậy sẽ đưa bản lỗi lên lại. Đội sẽ gắn tag mới (ví dụ `v1.0.2`) khi sửa xong.

Nhắn đội **"Đã quay lui app về v1.0.0"**, kèm:
- dòng cuối của R4;
- ảnh chụp R5, R6, R7.
